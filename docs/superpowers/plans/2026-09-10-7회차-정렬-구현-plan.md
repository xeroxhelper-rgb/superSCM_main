# 7회차 프로젝트 기준 정렬 구현 계획

> **For agentic workers:** 작업을 단계별로 실행하고 각 단계의 테스트 결과를 확인한다.

**목표:** 현재 프로젝트를 7회차 기준의 실데이터 조회·분석·관리 구조로 단계적으로 확장한다.

**아키텍처:** 기존 인증·Agent·다크 Workflow를 보존한다. Supabase는 `raw` 원본, `core` 정책·계산, `analytics` 화면 조회라는 경계를 유지하며, 실데이터 View를 `lib/scm.ts`를 통해 화면과 Agent가 공동 사용한다. 새 Route와 관리자 기능은 기존 Route와 병행해 추가한다.

**기술 스택:** Next.js 15 App Router, React 19, TypeScript, Supabase, 순수 CSS, Node test runner.

**기준 문서:** `작업.md`, `AGENTS.md`, `SCHEMA.md`, `ARCHITECTURE.md`, `design.md`.

## 전역 제약

- 기존 `getLeadtimeGap`, `getStockoutRisk`, `getStockoutKpi`는 호환성을 위해 유지한다.
- Supabase 원본 `raw` 데이터는 직접 수정하지 않는다.
- 화면·Agent는 `analytics` View를 조회하고 계산은 DB 또는 순수 모델에서 수행한다.
- 계산 불가 값은 `0`으로 보정하지 않고 `null`과 `reason_code`를 유지한다.
- secret/service key를 클라이언트에 노출하지 않는다.
- 새 CSS 프레임워크를 설치하지 않는다.
- 기존 레거시 Workflow 컴포넌트는 필요한 경우 외에는 수정하지 않는다.

## 단계

### 1단계: 기준과 현재 DB 계약 확인

- 현재 Migration과 기준 Migration의 객체·의존 순서를 대조한다.
- 현재 프로젝트와 충돌하는 객체는 `create if not exists`, `alter` 중심으로 조정한다.
- 실데이터 View의 실제 컬럼을 `scm-model.ts` 정규화 후보로 기록한다.

### 2단계: DB Migration 추가

- Step 3~7 Migration을 현재 프로젝트에 추가한다.
- Agent 대화 저장 Migration을 추가한다.
- 신규 객체의 RLS, grant, 계산불가 정책을 확인한다.
- Supabase SQL Editor에서 실행할 수 있도록 Migration별 독립 실행성을 유지한다.

### 3단계: 조회 계약 전환

- 실데이터 수요·출고·OL·BOM 타입을 추가한다.
- `lib/scm.ts`에 실데이터 View 조회 함수를 추가한다.
- 기존 함수는 삭제하지 않고 필요하면 alias를 제공한다.
- 조회 오류와 빈 결과를 구분한다.

### 4단계: 사용자 화면과 메뉴

- `/dashboard`, `/analysis/demand-profile`, `/analysis/model-comparison`을 추가한다.
- `USER_MENU`, `ADMIN_MENU`, `menuForRole` 구조로 메뉴를 정리한다.
- 기존 Workflow Route는 레거시 호환용으로 유지한다.

### 5단계: 관리자 운영 화면

- 수요·데이터 적재·Forecast·Backtest·Champion·설정 화면을 추가한다.
- 관리자 변경은 Server Action과 DB RLS 양쪽에서 보호한다.
- Import의 parse → validate → commit → rollback 흐름을 분리한다.

### 6단계: Agent 운영 연결

- `/api/agent/stream`을 추가한다.
- 기존 orchestrator와 conversation 저장을 재사용한다.
- API Key와 원본 Tool 데이터는 서버 밖으로 전달하지 않는다.

### 7단계: 검증

- `npm test`
- `npx tsc --noEmit`
- `npm run build`
- Route·메뉴·권한·실데이터 View 계약 테스트
- 변경 파일과 미완료 운영 설정 기록

## 중단 기준

- 현재 Supabase 구조와 Migration의 충돌을 안전하게 해결할 수 없을 때
- 기존 인증·Agent·레거시 화면을 보존할 수 없을 때
- 실제 View 컬럼이 기준 문서와 달라 정규화 계약을 확정할 수 없을 때

이 경우 임의로 컬럼이나 데이터를 만들지 않고, 충돌 객체와 필요한 실제 스키마 정보를 보고한다.
